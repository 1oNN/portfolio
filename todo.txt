  🔴 CRITICAL — fix before deploy (security)                                                                                                                                                                               
                                                                                                                                                                                                                           
  1. Admin password leaks to every visitor's browser
                                                                                                                                                                                                                           
  next.config.js:6-8 exposes ADMIN_PASSWORD via the env: {} block. Next.js inlines anything in env into the client JavaScript bundle. Anyone visiting your site can find your admin password in DevTools → Sources.
  Fix: delete the env block. process.env.ADMIN_PASSWORD already works in middleware (Edge runtime) and API routes (Node runtime) without exposing it.

  2. Auth token is the password (base64 encoded)

  middleware.ts:7, app/api/admin/login/route.ts:16, app/api/blog/route.ts:7, app/api/blog/[id]/route.ts:7 — all use btoa(password) as the cookie token. atob() reverses base64 instantly. Anyone reading the cookie reads
  your password.
  Fix: sign a JWT (jose library) or store opaque session IDs server-side. Use HMAC over {userId, exp} with a SESSION_SECRET env var.

  3. Hardcoded fallback password "admin123" (4 places)

  middleware.ts:7, app/api/admin/login/route.ts:11, app/api/blog/route.ts:7, app/api/blog/[id]/route.ts:7. If ADMIN_PASSWORD is unset in prod, anyone can log in.
  Fix: throw on startup if env is missing. No fallback.

  4. No rate-limit on admin login + non-constant-time compare

  app/api/admin/login/route.ts:12 does body.password?.trim() !== expected (string equality is timing-attackable) and there's zero rate-limiting. Brute force a 4-char password in seconds.
  Fix: crypto.timingSafeEqual + login rate-limit (5/min/IP).

  5. XSS via blog post markdown

  lib/markdown.ts only escapes inside code blocks. Headers, paragraphs, list items, and links pass raw HTML through to dangerouslySetInnerHTML at app/blog/[slug]/page.tsx:140 and the admin preview. An attacker who gains
   admin (see #1–#4) injects <script> everywhere. Even without that, your own admin can footgun.
  Fix: swap parseMarkdown for marked + DOMPurify, or use react-markdown with rehype-sanitize.

  6. Email-field XSS in outbound SES email

  app/api/contact/route.ts:141 interpolates ${email} raw into HTML. The regex /^[^\s@]+@[^\s@]+\.[^\s@]+$/ allows <script>@x.com. Affects the recipient (you), but still an issue.
  Fix: sanitize email through the same sanitize() already defined.

  7. npm audit: 6 vulnerabilities

  - Next.js 15.3.0 (critical): cache poisoning, image-optimization content injection, HTTP request smuggling, SSR DoS. Upgrade to 15.5.x.
  - nodemailer 6.9.14 (high): SMTP command injection, recursive-DoS — and you don't use it (you switched to SES). Just remove it and @types/nodemailer.
  - uuid v13.0.0 (moderate): missing buffer bounds check; bump to ^11.0.0 or ^14.0.0. (Note: v13 is also a misversion — npm resolved it weirdly.)
  - postcss/fast-xml-parser: transitive, fixed by Next + AWS SDK upgrades.

  8. .env.local committed to disk with secrets

  The file is in .gitignore (good), but it contains GROQ_API_KEY=gsk_… that may be live. Rotate that key now if it ever leaked or got pushed before the gitignore was added. AWS keys look like dummy text — verify and
  rotate if real.

  9. In-memory rate limiter useless on serverless

  app/api/agent/route.ts:8 stores rate-limit state in a module-level Map. Lambda cold starts reset it; warm instances are siloed per container.
  Fix: DynamoDB-based limiter or Upstash Redis.

  10. Missing security headers

  - No Content-Security-Policy (huge for a site that does dangerouslySetInnerHTML)
  - No Strict-Transport-Security (HSTS)
  - X-XSS-Protection: 1; mode=block is deprecated — set to 0
  - Add Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Resource-Policy: same-origin

  11. Other API holes

  - /api/blog PUT/DELETE: no CSRF token (relies only on sameSite: strict)
  - /api/contact and /api/track-download: no rate limit at all
  - /api/analytics: in-memory store; useless and wide open if ANALYTICS_SECRET unset
  - Response error message leakage minor but acceptable
